# Reference-driven motion and localized footage edits

1. Separate the deliverables at intake. An editable character, an authored studio render, a source-preserving shot edit, and an interactive photo-textured rig have different acceptance criteria. Establish the frame or sample boundaries, accepted changes, and comparisons for each.
2. Catalog subject-specific observations separately from general anatomy references. Record camera and lighting limitations, whether positions are observed in the image or inferred in depth, and which apparent views are mirrors. Count distinct exposures and independent camera positions separately. Use visible landmarks, proportion ratios and uncertainty across independent views to set a fit target. An agreement percentage on a selected visible ratio cannot certify hidden geometry or identity.
3. Fit the standing character first. Use a versioned bind coordinate system with stable semantic landmark IDs for the face, joints and anatomy. Keep source coordinates, modeled coordinates, bone association and provenance in the register. Hash its canonical bytes and verify published positions at load. Preserve the reference register across animation and apply its bone binding to move the displayed markers. Validate with a deliberately changed register.
4. Retarget observed motion on a rational clock with fixed segment lengths. Keep root motion, joint articulation and camera motion independent. Specify side and forward directions relative to the subject, then verify them at multiple angles. Use inverse kinematics for visible support and document the assumptions for occluded joints. Smooth transitions across retained joint ranges and test jump, contact, fast turns and holdout poses. Keep a static or reset state for comparison.
5. For the studio render, conserve the reference's timing when appropriate and use a close view for texture and a full-body view for limb visibility. Check the evaluated camera margins throughout the shot. Review seams, fitted facial texture, materials, shadow, and silhouettes at the target resolution. Resolution establishes raster size. Likeness needs a separate image comparison.
6. When the user wants the rest of a recording preserved, edit only the authorized interval and affected region. A wider view cannot recover pixels hidden by physical foreground geometry. Use nearby views for shape and texture, generate only the missing region and necessary surrounding plate, and log what is estimated. Preserve untouched native YUV cells, accounting for shared chroma blocks. Keep the original soundtrack and rational presentation clock. If the chosen decoder supports in-band size changes, align coded sequence transitions with independently decodable frames and verify both directions in the target browser. A single-size delivery is another option when the player requires it. Check each unchanged frame or region, audio packet/sample equality where required, continuous timestamps, and playback across aspect transitions. [Code-generated video workflow](code-video.md)
7. For live footage posing, produce a frame-indexed manifest with shot boundaries, native dimensions, per-layer projected landmarks, confidence, soft foreground masks, and protected graphics. Estimate occluded background from neighboring observations in the same shot, falling back to a local reconstruction only where evidence runs out. Treat a mirror as a separate layer linked to the same motion. Keep the source video untouched at neutral. Track the affected union of the original and moved foreground when checking pixel invariance. Document artifacts at disocclusions and the limits of a camera-plane rig. [Interactive app integration](../../full-stack-app-creation/references/footage-motion-review.md)
8. For a private source comparison, read the caller's recording in place. Process subject-derived landmarks, masks, fitted motion, textures, and comparison renders in temporary storage and remove them after verification. Keep only de-identified results, such as check counts and pass/fail outcomes. Use the synthetic fixture for retained smoke-test evidence.

## Synthetic reproduction

The [fixture generator](../assets/footage-motion/generate.py) creates geometric figures, a protected source overlay, two coded widths, and a reflected layer in a three-shot silent MP4. The atlas uses projected landmarks and known synthetic background. This teaches the runtime contract. A production input requires task-local tracking, masks, and plate reconstruction. Use the PyAV, NumPy and Pillow versions in the [video fixture requirements](../assets/code-video/requirements.txt) with a PyAV build that supports libx264. Use the existing video fixture for soundtrack and packet-preservation validation. [Capture inventory and comparison](footage-motion-capture.md)

## Regenerate a source-only editor

1. Index the actual decoded presentation clock. Generate pose and foreground mattes, pose-guided face and hand geometry, then skin weights, stabilization tracks, and motion observations from the same input. Fit motion from chronological samples and retain projected depth as an estimate.
2. Preserve the original for native display and checksum it in memory during validation. Verify that the 4K encode retains composition, decoded picture timestamps, duration, and AAC content and timing. Carry provider-neutral feature labels and normalized local anchor coordinates across tracked frames.
3. Keep the model in the source camera plane. Run view zoom and pan separately from deformation. Use bounded local support and foreground-aware reconstruction to preserve surrounding scenery. Treat uncovered background and hidden anatomy as inference limits.
4. Rebuild with public inference dependencies and the caller's video as the only subject-specific input. Run the browser tests on freshly constructed state. Hold derived media and tracking only in a temporary local session and retain de-identified results.
