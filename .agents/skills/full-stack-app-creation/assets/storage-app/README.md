# Portable storage dashboard example

This authored example combines a loopback Python service, buildless UI, SQLite history, explicit acceptance rubric, and opt-in native SMART authentication. All demo devices and identities are synthetic. No original host data, authenticated readings, credentials, runtime databases, or screenshots are bundled here.

Run `python3 -B server.py --port 0` from this directory and open the printed local URL. `./start.sh --port 0` works from any working directory. Python 3.10+, Linux lsblk, procfs and statvfs are runtime prerequisites. Root is not needed for ordinary inventory. Start on the demo source when host inspection is not authorized.

For SMART scans, install system smartmontools and polkit through the target system's normal administration process. The scan discovers pkexec/smartctl, verifies root ownership and non-writable ancestors, and invokes only fixed read arguments for inventoried devices. A desktop authentication agent and an authorized human are indispensable for actual privileged reads. Do not launch real authentication during automated reproduction. No policy files, password cache, broad disk-group membership or sudoers changes are installed. Policy may prompt per drive; session-retained readings are data, not retained authority. Each reading displays its original collection time. Cancellation stops subsequent prompts; timeout is per device.

QA needs Node 20+, an existing Chrome/Chromium executable (or BROWSER_EXECUTABLE), and `npm ci --ignore-scripts --no-audit --no-fund`. package-lock.json pins playwright-core and the Node-20-compatible axe adapter. Do not copy installed dependency trees. Fixture-only checks: `node tests/core.test.mjs` and `python3 -B -m unittest discover -s tests -p test_jit.py -v` (JIT tests mock privileged execution; system executable prerequisite still applies). Full read-only integration: `python3 -B scripts/validate.py --live-host --output <fresh-task-evidence-directory>`. It records commands, exit codes, source hashes, 20 scored acceptance scenarios, downloads, actual HTTP and desktop/mobile/error screenshots. Its browser never clicks the real authorization button. Synthetic tests do not establish hardware health.

The server uses per-process CSRF tokens, exact Origin/Host checks, body-free scan POST, fixed argv, timeouts and a single scan worker. Passwords are entered only into the native desktop prompt, never into a browser textarea. The button invokes authentication only after explicit user action. Test successful results, cancellation, denied/no-agent responses, malformed output, concurrent requests and unsafe device paths. For a real user test, get authorization for the fixed reads, let the human handle the system prompt, compare CLI/API/rendered status and timestamps, verify the server UID, and retain fresh evidence outside the skill. Retain/stop the local preview according to the requested lifecycle.

Mounted usage deduplicates filesystem identities. Physical capacity and mounted usage have distinct denominators. Used + available + reserved balances to mounted total. Unmounted usage is unknown and swap is distinct. Device-reported SMART status is independent of capacity thresholds. Changes to inventory can affect global capacity history.

Source: telemetry.py (collection/accounting/history), jit.py (one-shot native authentication), server.py (HTTP), web/ (complete UI), tests/ (fixtures, HTTP and browser checks), scripts/validate.py (scoring/evidence), reference/storage-sweep.sh (original generic read-only inventory input), PRODUCT.md (example requirements and rubric). These are generated task sources; dependencies retain their own package licenses. The shell reference is not executed by the dashboard. This is a portable starter, not a reproduction of a particular machine.
