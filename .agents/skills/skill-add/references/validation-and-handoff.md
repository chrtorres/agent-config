# Reproduction validation and handoff

1. Review the [existing-skill comparison](skill-comparison.md): evidence-backed factors, correct arithmetic, inclusive 75% threshold, compatibility, routing decision, and any explicit user override. Verify relevant feedback is paired with implementation responses and observed outcomes. Use the resulting skill and bundled resources as the instructions. Identify hidden reliance on the previous conversation, original worktree, scratch dependency installation, fixed port, browser path or external account.
2. Copy templates into a fresh task workspace when they are intended for adaptation. Preserve relative layout. Keep generated evidence and runtime state outside the canonical shared skill.
3. Check prerequisites without changing system configuration. Run available checks; classify unavailable runtimes/services as blocked rather than algorithm failures or passes. Acquire isolated dependencies only within current authorization and environment rules.
4. Run behavioral tests and the smallest representative workflow. Inspect actual artifacts and outputs. If the workflow produces a visual interface, drive relevant controls and inspect screenshots. If it produces compiled objects, verify actual build artifacts rather than a launcher message.
5. After changes, rerun affected checks. Record material failures and corrections, then report the final observed outcome. Historical fixture results remain distinct from the current run.
6. Review completeness, portable parameters, scope, provenance, references, binaries and rendered assets for hidden private values. Automated file hashes and text scans complement this review but do not replace it.
7. Validate the entrypoint and generate/verify the final bundle index. Make no further source edits without updating the index. Its own generated index is excluded from its snapshot; other resource files remain covered.
8. Preflight and create directory symlinks in intended model discovery locations. Verify entrypoint and supporting resources through those links. Never copy the skill into separate model directories or overwrite an unrelated existing entry.

Deliver a concise result with the extend/create decision and duplication score (or why no candidate could be scored), canonical skill link, invocation, resource inventory link, current validation summary and discovery-link status. State generalized value categories and essential external prerequisites. If an indispensable resource cannot be bundled or regenerated, say exactly what is missing and how it affects reproduction.

This procedure itself has behavioral helper tests under `tests/`. They verify changed/missing/extra resources, portable internal links and traversal rejection, ignored runtime material, unsupported objects, deterministic indexing, discovery conflicts and idempotent linking. These tests establish the packaging tools' tested behavior; they do not validate every future skill's semantics.

The bundled [helper test results](helper-test-results.txt) record a successful run from an isolated copy. The [synthetic fixture skill](../assets/fixture-skill/SKILL.md) includes a small binary object and its own index, so an agent can exercise object capture, verification and deliberate mutation without private inputs. Its bytes and skill name are synthetic test data. Use a copy when experimenting with changes.
